# 双目录版本验证范围

当前未发布 schema-4 使用固定程序入口 `<store>/.cdet/bin/` 和完整数据根 `<store>/<组件>`。Codex 交给官方安装脚本，Mihomo 优先官方控制 API；不再保留历史版本仓库、独立 rollback、数据库改写或通用事务回放。

## 持续验证要求

| 范围 | 必须证明的行为 |
|---|---|
| 完整迁入 | 确切数据根全部复制，未知格式、配置/认证/会话/数据库字节及普通文件 mtime 保持，原件不变 |
| 活跃进程 | CLI、daemon/app-server、打开文件、共享映射及旧 HOME 使用者阻止危险迁入/重绑；不自动停止进程 |
| 运行互斥 | cdet 启动进程的共享 lease 与组件本地写操作互斥；外部启动仍查进程，Mihomo 官方更新 POST 不阻断自身运行 |
| 链接边界 | 外部或循环链接、特殊文件和已识别外部资源被拒绝；内部链接副本可重定位 |
| 挂载定位 | 两根共同或单独移动后核身份、重建入口及已知官方 Codex 链接；缺失存储不创建空替代，同 ID 多份副本需明确选择 |
| 上游安装更新 | 只执行假 curl 返回的本地模拟脚本；确认前不执行安装器、下载程序或更新 POST；代理环境一致 |
| 程序归属 | 官方自更新不因历史程序摘要误判外改；工具入口和身份仍受保护 |
| 数据保留 | 更新不由工具改写用户数据；卸载保留完整 HOME 和未知文件；已发布 HOME 不自动回滚删除 |
| 发行 | 临时 HOME、服务哨兵、四平台静态包校验和本机只读冒烟不触碰真实组件 |

## 真实边界

CDEToolkit 只做完整 HOME 文件复制和环境切换，不维护 Codex 数据库表结构、索引、WAL 或格式兼容规则。外置 `CODEX_SQLITE_HOME`、显式 `sqlite_home` 和外部链接通过轻量预检拒绝不完整迁入；keyring 认证不随目录移动。

挂载修复只额外处理已知官方 Codex `current` 和可见命令符号链接，将它们安全转为相对链接，不改写数据内容或数据库。其他内部绝对路径、外部项目、附件、MCP 和插件依赖仍需单独处理。用户既有的整 HOME 移动验证不等于本轮运行过真实 Codex，也不构成所有上游版本 resume 功能的保证。

## 验证记录

本轮只允许源码与隔离模拟测试；不发布、不切换真实入口、不执行真实官方安装器、不安装或启动真实服务、不读取真实数据构造夹具。实际检查结果以当前测试输出为准。

此前 schema-3 在 macOS/Linux 的整库、race、CLI、四平台包检查已完成，但该结果仅属于当时实现，不能作为本次 schema-4 上游安装更新路线的通过声明。旧数据库实验和通用 journal 的故障注入用例已退役；保留目录复制、源不变、进程检查、路径重建、更新与卸载数据保留的回归。

2026-10-17 schema-4 最终验证：

- macOS `make check smoke` 通过，含格式、Shell 语法、vet、全库 race、CLI 隔离、包校验与只读冒烟；核心 race 用时 81.206 秒。
- Linux amd64 测试二进制在 SSH Zenith-Dev 的独立 `/tmp` 目录通过全部 77 项顶层测试；只上传测试二进制和公开元数据夹具，临时目录已清理。
- Linux/macOS 的 amd64、arm64 四平台交叉构建通过。
- 覆盖官方三处链接的完整安装/挂载迁移/卸载、旧存储副本仍存在时显式重绑、跨 exec 运行锁、预览后挂载消失不重建旧路径、安装失败保留 HOME 与迁入收据重试。
- 官方脚本及更新接口均使用模拟；没有执行真实官方安装器、真实组件更新、发布或真实入口切换。配置、认证、会话与数据库夹具逐字节或整树核对。

## 官方安装更新职责边界复审

2026-10-17 再次从当前源码独立复核，新增模拟回归先复现问题，再修复：

| 问题 | 修复 |
|---|---|
| 下载/安装期间管理目录消失，后续写入可能重新创建旧路径 | 在外部命令和下载后复核双目录身份；受管原子写入只创建现有管理根的子目录，不创建管理根 |
| 重试安装时，保留的 HOME 或官方程序写入父目录被换为外部链接 | 执行前及下载后检查物理数据根、上游写入父目录与已知程序链接；新装拒绝未登记的固定程序或辅助入口 |
| 下载命令的 stderr 混入脚本内容 | 分离、有界捕获 stdout 和诊断；只将 stdout 交给 shell |
| 继承的 curl 配置可能改变官方脚本及其子下载的输出位置 | 临时 HOME 同时隔离 CURL_HOME/XDG_CONFIG_HOME，首次 curl 禁用户配置并限制 HTTPS 重定向；代理与 CA 环境仍可注入 |
| 已安装程序的入口保存失败，重试 install 跳过修复 | 在预览阶段检查入口冲突；重试只重建缺失入口，不重新安装程序 |
| HOME 为目录别名时，字符串比较遗漏整 HOME 迁入 | 使用文件身份检查，拒绝把整个用户 HOME 当作组件源 |
| 外网代理配置错误遮蔽本地版本、离线包和本机控制接口 | 本地操作不依赖外网代理解析；网络请求仍使用明确的代理环境 |
| 确认后控制器上线，离线计划可能变为会重启服务的在线更新 | 在线路线必须在预览阶段明确；执行期间不暗改路线，组件变忙时拒绝并要求重新预览 |

不新增运行依赖、持久化路径字段、版本仓库、回滚记录或通用事务机制。既有完整源和已发布 HOME 始终保留；卸载对固定程序软链接只 unlink，不跟随删除外部目标。

本次复审新增 19 组回归。macOS `make check smoke`（含全库 race、CLI 隔离、包校验）通过，核心 race 用时 97.543 秒；后补的更新路线确认回归另行通过 race。最终源码在 Zenith-Dev 临时目录通过全部 96 项 Linux 顶层测试，远端临时目录已清理；最终四平台交叉构建与 `git diff --check` 均通过。测试安装器、控制器、软件版本输出和数据均为模拟夹具，未执行真实生命周期操作。
