# 双目录轻量设计（schema-4）

CDEToolkit 只管理两个根目录和组件入口。已有组件完整迁入；没有组件则安装。软件自己的安装、升级和数据格式由上游负责，工具不维护应用私有数据库。

## 固定布局与清单

- `prefix/bin/` 存 cdet 与组件入口。
- `prefix/config.toml` 记录两个根的关系和身份，`.instance` 随安装根移动。
- `store/.cdet/state.json` 记录组件当前安装状态、后端、来源、必要的摘要及生成入口归属。
- `store/.cdet/bin/{codex,mihomo,gds}` 是固定程序入口。
- `store/{codex,proxy,gds}/` 直接存完整组件数据；Codex 环境为 `CODEX_HOME=store/codex`。

两根互不包含，不保存任意多根运行路径。没有版本 map、内容寻址仓库、`current` 链接、上一版本和永久迁入来源记录。旧实验 schema 明确拒绝原位复用。

## 上游职责

Codex 的程序安装和更新只调用官方安装脚本。统一传入受管 `CODEX_HOME`、`CODEX_INSTALL_DIR` 与非交互环境，并使用临时 HOME 隔离安装器的 Shell 写入。下载和程序执行保留有效的现有代理环境。对官方管理程序的后续合法自更新，不以最初下载摘要持续阻止执行。

Mihomo 优先调用本地官方控制 API 更新；API 不适用时才使用经过校验的发布包替换程序。官方更新可能重启进程，必须在执行前展示。已调用官方更新后遇到错误不静默换另一条更新路径。不接管 systemd、Supervisor 或自动启动服务。

GDS 显式可选，要求本地独立包，不参与默认安装或更新。cdet 自身使用项目安装器更新，不提供独立自更新/回滚子系统。

`status` 只查当前本机版本；`versions` 才访问上游。更新规划只做只读查询，确认后的 Apply 才运行安装器、下载或 POST。预览保持零持久写入。

## 完整目录迁入

`--from` 是一次性的确切来源，不是长期托管路径。来源原件保留，不沿名称自动下钻 `data/`。Codex 只复制完整 HOME，不筛选对话、不读写数据库结构。

复制普通文件、目录与合法内部链接，保留权限和普通文件 mtime。内部规范绝对链接仅在副本中转换；外部链接、循环、特殊文件和已识别的外置资源拒绝迁入。外置数据库仅通过已知环境/配置键轻量预检，不增加数据库驱动。

迁入前和提交前检查活跃进程、完整来源及一次性复制校验。复制在存储内的临时目录完成，同文件系统 rename 发布。后台 daemon/app-server 仍访问原 HOME 时也拒绝迁入或挂载重绑。工具不终止进程。

系统 keyring、外部项目/附件、MCP 和插件依赖不会自动搬迁。HOME 文件复制及入口修复不能证明这些引用已适配；工具不改写普通配置、会话或数据库。

## 最小操作安全

操作对两根加锁、核对安装身份，按组件顺序执行。多组件不要求 all-or-nothing。文件使用临时副本和原子替换；完整 HOME 发布后不自动删除。未完成迁入只保留核对归属所需的短期小标记，失败保留可诊断位置，不提供通用 journal 回放和 `repair --recover`。

`cdet exec` 及生成入口启动的组件持有可跨 exec 的共享运行锁；本地替换、迁入、路径修复取得同组件的独占写锁。这套锁只约束经 cdet 启动的进程，外部直接启动的组件仍须退出，并由进程预检查找。Mihomo 官方在线更新 POST 不取得阻断其自身运行的独占锁，由上游处理正在运行的程序。

卸载只处理受管程序和入口，保留整个组件数据根和未知文件，没有递归数据 purge。程序元数据只描述当前状态，不是用户数据备份。

## 挂载变化

两根一起移动时通过新 CLI 位置和相对关系寻找存储；仅存储移动时由 `repair --store` 选择。始终核对身份，同 ID 多份副本要求明确选择，缺失存储不会创建空替代目录。

修复重建 CDEToolkit 引导、入口和环境，也安全重绑已知官方 Codex `current` 及可见命令符号链接，将其转成相对链接。只管理这些已知链接，不改写配置、认证、会话、数据库或普通文件内容。不恢复旧挂载、不修改 Shell，其他内部绝对路径仍需单独处理。原来源的最终清理由验证后的独立动作完成。
