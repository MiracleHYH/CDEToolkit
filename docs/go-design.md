# STK Go：组件管理与文件生命周期

STK 是按需执行的单机开发环境管理 CLI，核心是 Proxy/Codex 接管、安装、更新、卸载与路径重建。
GDS 保持显式可选，不扩展为任务平台、通用包管理器、插件系统或额外守护进程。

## 持久状态

一个 `STK_HOME` 包含 `config.toml`（用户意图）、`state.json`（目录根、组件位置、文件归属）、
`stk`、`bin/`、`env.sh`、`services/`。后四项可重建；配置、认证与会话属于应用数据。
组件同时记录来源、是否拥有二进制、展开后的二进制摘要，以及可选的官方版本/包摘要/平台。
自定义下载 URL 不写入状态或计划 JSON，避免带入临时令牌。

根目录用 local/projects/data 等逻辑名。路径保存为根目录与相对路径，独立 data 根与工具根解耦。
管理目录移动后，从同一实例记录重算同盘 local/projects；独立 data 根需显式映射。
Linux 记录挂载类型并检测挂载降级，GPFS 类型不作为身份的唯一证据。

## 发现与接管

按登记信息、显式路径、常见布局、PATH 与有限搜索目录发现；不执行程序、不递归扫描实验数据。
已有有效 Codex 主入口优先；歧义要求明确选择。已登记安装失效不静默换装。
`repair --search DIR` 可以按已保存的程序摘要匹配移动后的文件，多个匹配停止。

外部程序原位使用，不自动据为己有。Codex 主目录保留认证、会话、SQLite 和其他文件。
修复已识别的失效 package 链接时生成相对链接。默认不改外部配置内容；明确 `--manage-config`
后才迁移 Codex 已知路径字段与代理 YAML 的路径字段，TOML 可能重新排版。
Conda/venv 内嵌 prefix、任意历史数据库路径与未知第三方配置不做盲目替换。

## 一条安装与更新流程

`install` 优先走 `setup` 接管；没有候选时才用内置官方源。`setup` 不隐式联网。
官方发布解析使用固定仓库、稳定 tag、精确资产名和 SHA-256；只支持已明确映射的系统/架构。
Mihomo amd64 选择 v1 或 compatible，Codex Linux 选择 musl CLI。

本地文件、自定义 HTTPS、官方发布最终都进入同一个 artifact 解码器；不执行任何安装脚本或候选程序。
下载、展开、归档项数均有上限；只读取指定模块的一个程序，不按压缩包里的路径落地。
官方二进制额外校验 ELF/Mach-O 平台。程序写入 STK_HOME/tools/NAME/COMMAND，运行目录与用户数据原位保留。

`update` 只更新已登记模块；默认只选择拥有的 Proxy/Codex。外部程序要求由原安装器更新，
或者明确 `--takeover` 后使用 STK 副本，不删除/改写原安装。相同官方包与本地摘要一致时不重复下载。
有明确版本参数时可切到指定稳定版。GDS 必须给出自己的 artifact，不隐式在线安装。

STK 自更新也使用 artifact 流程，目标仅为 STK_HOME/stk。尚无配置的自身发布仓库，需显式 URL/文件及摘要。
不更新 Git checkout，不跑 post-install，不将软件包管理行为绑定到源码仓库。
`repair` 只在管理程序缺失时重建，不因从旧副本调用而降级当前管理程序。

## 卸载与数据边界

卸载只移除固定允许范围内、存在归属摘要且内容匹配的生成文件；外部程序完全保留。
不递归删除目录，不 purge 组件主目录、配置、认证、会话、数据库、缓存或未知文件。
全卸载还删除共享管理入口和登记的 Shell 块。Shell 块外的用户改动逐字节保留，块本身被改则停止。
保留空模块的状态/配置与事务备份，完整卸载重复执行为零变更，可由外部新版本再次接管。

## 环境与服务

env.sh 不导出全局 HTTP 代理。Codex 子进程只设置已登记的应用代理与 CODEX_HOME；无受管代理时保留调用方环境。
Shell 只有显式登记才写受管块，块位于交互提前返回之前。卸载或改路径后需使用新 Shell；不会修改父进程环境。

Supervisor/systemd 模板只写在管理目录，默认 autostart=false。服务后端仅复用现有控制器。
明确的 `--service-file` 才允许 setup/repair 更新选定 section 的路径，更新和卸载不改外部服务定义。
安装、更新、修复、卸载不执行服务控制、daemon-reload 或进程版本探测；运行态与文件态分别报告。
更新后仍运行旧版本的进程，以及卸载前停止/解除注册，均是后续显式操作。

## 事务、预览与恢复

文件写入、链接、目录创建、remove 共用 Plan/Apply。所有负载在写入前下载和校验。
执行前加锁并复核目标指纹，同时验证从 New 读入的配置/状态未被后续操作覆盖。
备份仅覆盖本次改动文件；失败逆序恢复，pending.json 支持中断恢复。
恢复前再次验证当前目标仍为操作前/后内容之一；有后续用户修改时保留记录并停止。
恢复位置不可用时不创建旧挂载的替代目录。

status/scan/doctor 不联网、不写文件。doctor --exec-check 是明确的版本探测，GDS 不运行 monitor。
在线 --dry-run 只读取发布元数据，不下载程序；deferred 计划不能 Apply，执行时需重新解析、校验和生成完整计划。
本地 artifact 的预览包含完整摘要。计划不输出文件内容或 URL 凭据。

## 测试与兼容

单元测试使用临时目录和 TLS 模拟上游；CLI 集成测试使用临时 HOME、假程序和假服务控制器。
涵盖挂载改名、重复执行、离线/在线安装、更新/迁入副本、SHA 错误、不安全归档、平台错误、
元数据并发漂移、事务失败/恢复、文件归属、卸载保留数据，以及真实服务控制器零调用。
Linux 静态构建在远端临时目录执行相同测试，不针对真实 STK_HOME 执行生命周期命令。

当前不导入 Bash 状态、不切换现有 Bash 入口。旧实现冻结，新发行包仅包含 Go 程序。
遗留源码删除条件见 legacy-boundary.md。

## 2026-10-17 审计修订

路径历史保存为 state.path_aliases，既支持挂载根，也支持组件主目录单独迁移。
当前根同时作为恒等映射，避免嵌套目录前缀在重复修复时持续展开；仅移动 STK 时保留仍存在的应用根。
配置迁移按 schema 位置收敛，未知表、env 凭据和共享 YAML 锚点不盲目改写。

update 与 repair 分开：先修复目录根，再仅更新选定程序及受管模板。
成功更新的 last-update.json 与独立事务备份支持一次整批 rollback；相同位置且受影响内容未漂移时才执行。
挂载变化后的旧更新记录可以被下一次更新安全退役，不能直接重放其旧物理目标。

文件事务日志为 v2，绑定实例、管理目录和事务 ID，备份不复用其他事务的槽位。
备份后再次验证所有输入，每项写入前再验证目标；失败恢复先整体校验，逐项恢复也检查当前内容。
恢复目录发现新内容时停止并保留 pending，不递归删数据。原子写入保留已有 UID/GID 与权限。
最近更新所需备份保留，常规备份仅按记录与摘要清理，未知内容保留。

完整问题、修复依据、兼容边界和旧实现清理条件见 go-safety-audit.md。
