# Nido Go 设计（当前未发布源码）

Nido 是开发容器内面向当前用户的轻量环境管理工具，以 nido 交互菜单为主入口，明确命令保留给自动化。它不管理云平台、镜像、驱动、CUDA 或 Python/Conda 内部环境。

## 边界

- 一个软件目录，默认 ~/.nido；外部数据不搬入软件目录，不提供目录迁移或挂载历史修复。
- Codex 为外部辅助集成：目录关联、PATH、受管 .env 代理、官方安装更新；数据不透明，不管理 daemon。
- Conda/pip 为外部配置辅助：镜像及环境/缓存目录，不安装工具、不创建环境、不搬迁清理数据。
- Proxy 为内置用户级组件：保留原生 YAML、推荐 Quick Start、URI、listeners、分流、启停和程序更新；不接管系统网络。
- GDS 独立源码保留，退出核心注册、默认编译、CI 和发行。

## Go 结构

交互层负责导航/输入/预览/确认；管理层组合状态与配置；独立组件/集成实现操作。菜单与自动化共享同一写入路径，不引入动态插件、通用表单或事务引擎。

`internal/terminalui` 是唯一终端所有者，固定使用 Bubble Tea v2、Bubbles 的文本输入和 Lipgloss；最低构建版本 Go 1.26，用户运行不需要 Go。组件只提供状态函数和有稳定 ID 的动作，不自己读取按键或管理 ANSI。业务和状态查询串行调度到事件循环外，同一个 Manager 不并发读写；慢操作有超时和取消信号，终端仍能处理按键及窗口变化。无业务轮询、无空闲动画；颜色使用保守 ANSI，不查询终端背景造成启动等待。

外部配置结构安全检查与组件运行时可用性分离。路径不可用在相应组件报告，不阻断无关菜单；具体写入仍执行完整归属、权限、并发和路径校验。

## 网络

保存两个设置：GitHub Accelerate（none、HTTPS 前缀或 proxy）和 Proxy URL。GitHub 文件路线互斥：none 官方直连，前缀拼接后直连加速站，proxy 引用通用 Proxy 访问官方地址。前两条不使用通用 Proxy，无隐式环境继承或跨路线回退。引用 Proxy 时必须已有 URL，不重复持久化地址，也不保存 listener 绑定。

GitHub API 与其他 Nido 对外 API 使用通用 Proxy，不拼加速前缀；本地管理接口直连。Nido 启动的 Codex 官方安装更新命令以临时大小写代理环境和回环 no_proxy 使用通用 Proxy，None 清除继承值，不读取或修改 Codex 的运行 .env。旧明确配置仅有限读取并在保存时写为当前两个字段，旧 auto 或无效绑定由用户重新配置，不扫描或修复历史拓扑。

## Proxy 配置与更新

Quick Start 任何时候可进入；默认可 Skip 自行配置。替换前保留唯一 config.yaml.back，取消、校验失败、无变化不更新备份。锁内核对提交前身份，先备份后原子替换，不建立历史库或通用回滚。

用户安装或删除的是 Proxy 组件，Mihomo 内核随组件安装与删除，配置和数据保留；停机失败不删除。首次安装使用随 Nido 固定并核验大小与 SHA-256 的内核包，文件走 GitHub Accelerate，不依赖 API；仍验证下载边界和候选程序。后续内核更新通过受管实例的私有回环 controller 调用 Mihomo 原生稳定通道；更新订阅和 reload 同样委托 core。controller、程序映像和运行实例均需核验，不发送全局代理环境或 Nido 的 GitHub 加速策略。更新结果不明时不自动重试，不建立 Nido 版本仓库、回滚或通用事务。配置、启动、重启分别显式执行，不为原生更新隐式启动 core。

状态直接展示 core 与 proxy-group 的选择链及已有延迟；不自动测速、切节点或扩展连接/流量仪表盘。Quick Start 新配置默认 Provider interval=0，进阶周期设置留给原生 YAML。

## 安装与数据安全

旧 Bash 业务实现退出主源码。发行生成的 install.sh 自带压缩 Go 程序，极薄 POSIX 包装仅平台识别、私有临时解包、摘要/版本校验并调用，不另行联网或实施 Shell 菜单。所有选择由 Go 完成，标准输入管道不作为回答读取。代价是 base64 包装比压缩包增加约三分之一传输量，换取外层一次下载后即可使用同一 TUI，不增加下载前问答或 Shell 键盘实现。仓库保存模板，载荷仅生成到发行目录。

Go 生成 env.sh 与加载块，Shell 接入自愿选择；独立交互命令退出后恢复终端并保留有界、脱敏的结果摘要及实际路径激活命令。上游 Codex 官方脚本保持委托，取消仅终止本次调用创建的子进程组，不停止已有 Codex。

保留有界请求、大小限制、SHA-256/程序验证、安全原子写、并发检查、私有文件保护和只清理可证明归属字节。卸载保留用户数据。客户端不验 Sigstore，第三方脚本/包/摘要的信任边界不能由摘要消除。

源码整理不代表发行或部署；公开 v0.9.1 行为与验证范围见独立发行记录。
