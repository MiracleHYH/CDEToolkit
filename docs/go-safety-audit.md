# Go 版安全审计与旧实现清理清单

> **旧双目录及更早版本审计记录，不代表当前 Nido。** 本文主要对应已退役的 schema-1 原地接管模型，双目录时期记录另见 [two-root-audit.md](two-root-audit.md)。事务、回滚、完整迁入和挂载修复均非当前 Nido 功能；现行设计见 [go-design.md](go-design.md)，历史通过记录不等于当前实现验证结果。

审计日期：2026-10-17，包含首次安全修复和基于修复后源码的第二轮独立复查。范围：Go 全部实现、已有组件接管、挂载/目录迁移、安装更新、文件事务、卸载，以及旧 Bash 的静态引用链。
本轮仅修改源码并运行隔离测试，没有切换入口、注册/启动真实服务或改写真实应用数据。

## 第二轮追加发现与修复

| 问题 | 影响 | 修复后的行为 |
| --- | --- | --- |
| 首次安装中断后，恢复要求所有目标的父目录已存在 | pending 已落盘、程序尚未写入时，正常恢复被尚未创建的 bin/tools 目录阻塞 | 尚未写入的 absent 目标可直接跳过；需要恢复已有文件/链接时仍要求原父目录可用，不重建失踪挂载 |
| 回滚整体预检与逐项构造计划之间重新授权了当前内容 | 两次读取之间的用户修改或备份损坏可能被当成新基线或恢复内容 | 每项以更新记录中的 After 指纹授权，计划保存该指纹作为执行约束；每次读取备份均重新验 SHA-256，恢复读取后再查目标 |
| 文件删除、链接替换及目录创建缺少目录同步 | 崩溃时 namespace 与恢复材料的持久化顺序可能不一致 | 同步新增目录的各级父目录、链接替换与删除；pending 删除同步完成后才清理备份。文件系统明确不支持目录同步时保留兼容行为 |
| 成功更新保留了上一份 last-update 的事务快照 | 连续更新/回滚后留下不再被任何有效记录引用的小备份 | 提交成功后删除该事务内已验证的记录快照，仅保留当前回滚记录需要的备份；未知内容和旧版无法证明归属的孤立备份不删除 |
| 挂载变动后仍可直接执行组件或启动服务 | 二进制/主目录已解析到新位置，配置和外部服务定义可能仍含旧路径 | exec、版本执行检查、env、start/restart 要求先 repair；status/doctor 明确报告“路径待重建”；读取状态及显式停止仍可使用 |
| 禁用 Proxy 后 Codex 仍继承其 endpoint | 禁用的代理仍覆盖调用者的代理设置 | 仅继承已启用的 Proxy；Codex 自己明确配置的 endpoint 仍优先 |
| YAML 仅检查标量锚点 | 修改共享 provider 表可能影响未知字段；别名/合并表中的路径也可能被漏查 | 对已知路径字段作解析核对；共享表、标量锚点、别名和各级合并表需要迁移时停止，要求手动处理。不需要变化的共享结构原样保留 |
| 正常 Apply 未校验有效实例 ID 是否与现存状态一致 | 从其他实例带来的有效格式计划可能先写后在失败恢复时才被发现 | 写备份和目标前校验实例身份；初始化期间尚无 state 的情况仍可正常恢复 |

前述首次安装恢复、连续备份保留、迁移前执行、禁用代理四项均先由新增测试稳定复现失败；YAML 共享表/别名的五种原始形式也先复现，再扩展到合并表。
卸载复查没有发现新的递归删除路径；新增测试验证了“预览后用户修改则停止”，以及工具子目录中的未知实验文件、外部认证在整个 STK 卸载后继续保留。
复用原文件事务和路径校验，未增加运行时依赖、守护进程、新命令或另一套回滚实现。

## 首次审计发现与修复

以下前七项先编写回归测试，在修改前均能稳定复现；其他项在扩展审查和故障注入中补齐。

| 问题 | 原有风险 | 修复后的行为 |
| --- | --- | --- |
| 重复 setup 不验证已登记链接的后续变更 | 覆盖用户后来选中的版本/入口 | setup 和 repair 均检查链接归属与目标；显式更换程序时释放旧链接管理关系 |
| 根目录记录过早覆盖旧值 | 未接管或禁用的配置仍含旧路径，后续修复失去依据 | 持久保存逻辑路径映射历史；配置接管延后、部分卸载及多次迁移后仍有依据 |
| 无条件从 STK_HOME 推导 local/projects | 仅移动管理程序也会推移原应用目录 | 原目录仍可用时保留原记录；原目录消失时才采用已记录的相对关系，显式 root 优先 |
| repair 重建缺失的代理数据目录 | 用空目录掩盖丢失的挂载/数据 | 已登记数据目录缺失时停止；只有首次接管的默认运行目录可以新建 |
| 内容相同即取得生成文件归属 | 卸载可能删掉原先并不归 STK 所有的文件 | 相同内容仍需归属记录；仅允许显式安装时接管正在执行的 STK 自身文件 |
| 按任意嵌套键名迁移配置 | 改写 env/未知表中同名的 path/cwd 等值 | 限定 Codex 项目、已知 MCP 路径字段，以及代理 provider.path / external-ui；共享 YAML 锚点停止自动迁移 |
| 恢复记录未验证实例身份 | 另一实例的记录可重放到原实例路径 | 日志绑定实例、事务 ID 与物理管理目录；校验结构、变更类型、备份位置、摘要与目标当前内容 |
| 多次事务复用备份槽 | 后一次失败可能破坏前一次可用备份 | 每次事务独立目录；备份后、写入前再次检查输入；逐项写入前复核 |
| 只有失败恢复，没有成功更新回滚 | 更新后无法安全恢复旧程序与管理关系 | 增加 rollback / --dry-run，回滚最近一批更新，并将回滚自身放入文件事务 |
| update 顺带处理其他模块与路径 | 被无关组件故障阻塞，或隐式生成数据目录 | 更新只处理选定程序、受管模板与管理元数据；目录根变化先 repair |
| 路径历史、旧回滚记录与新更新的耦合 | 迁移后旧记录阻塞正常更新 | 不重放旧物理路径；新更新可以识别同实例旧记录、替换记录并安全回收经过校验的旧私有备份 |
| 健康的外部入口未登记 | 挂载移动后全局 codex 链接仍断裂 | 登记所选入口链接但不改健康链接；迁移后重建，禁止接管共享父目录链接 |
| setup 单独变更 Codex 主目录 | 混用旧程序、旧 package 链接与新数据目录 | setup / repair 共用模块定位规则，连同已授权配置路径一起重建，保留认证与历史 |
| 忽略 CODEX_HOME 环境设置 | 接管错误主目录，或在旧挂载创建空环境 | 尊重已有环境选择；不可用的环境路径不自动变成空目录 |
| 生命周期命令随 --search 改变 STK_HOME | 卸载可能转向另一管理实例 | 只有只读 scan 自动寻找管理目录，写操作始终使用明确的管理目录 |
| doctor --dry-run --exec-check 仍执行程序 | 预览具有执行副作用 | 拒绝矛盾参数；服务运行态操作与预览不混用 |
| 离线官方包内程序名带平台后缀 | 有效 Codex 离线包无法识别 | 按当前平台识别官方成员名；本地/自定义原生程序也验证格式与架构 |
| latest 指向较旧版本 | 静默降级已安装程序 | latest 拒绝降级，具体版本参数允许显式选择旧版本 |
| 读后写入与归属验证存在窗口 | 配置、Shell 或生成文件的后续修改被覆盖 | 计划保存读取内容/归属验证时的指纹；写入与恢复都复核，不依据后来的文件重新授权覆盖 |

原子写入替换仍存在的文件时保留其 UID/GID；权限使用计划指定值，外部配置沿用已有权限。无法保留归属时停止，不自动提升权限。
写入内容与文件名变更执行同步；目录同步的保证仍取决于底层文件系统支持，不把隔离故障注入等同于物理断电验证。

## 回滚与卸载的明确边界

- `repair --recover` 撤销未完成的文件事务；`rollback` 撤销最近一次已完成更新。两者均不控制服务运行态。
- 更新回滚前，受影响文件必须仍与更新后记录一致，备份摘要必须有效；后续修改时停止，不强行覆盖。
- 旧更新记录的物理管理位置变化后不直接重放。先 repair，再显式安装所需版本；后续的新更新仍可建立可用回滚记录。
- 如果恢复目录中出现未登记的新内容（包括认证文件），保留目录和 pending 记录，不能为清理目录而递归删除数据。
- 卸载只处理固定允许范围内、有归属记录且内容未变的文件。外部程序、组件内部链接、配置、认证、会话、数据库、缓存、未知文件均保留。
- 常规事务结束后仅清理自己经过验证的备份文件；最近更新所需备份保留，未知文件和目录不递归清理。
- 事务日志格式升级为 v2。旧版 pending 日志不会被猜测解释，需使用相应旧版或在备份后人工处理；本轮没有对真实日志执行迁移。
- 路径历史用于已知字段的前缀映射，不会重写 Conda/venv 内嵌 prefix、会话/数据库或任意未知配置。目录身份有歧义时要求明确选择。
- 指纹与文件锁用于检测正常并发改动，不能当作对抗恶意同 UID/特权进程的文件系统隔离；不对执行中的外部应用数据作快照或恢复。

## 旧 Bash 清理结论（CI 迁移前的审计记录）

以下保留两轮审计时的引用快照。之后 CI/发布已迁移，当前删除结果见 [go-ci-release.md](go-ci-release.md)。旧入口仍未切换，不能把“Go 不再依赖”直接视为“旧源码无人引用”。当时静态审查发现：

- `toolkit.sh` 仍直接 source 旧 lib，包括 lifecycle、transaction、codex、service、Git/SSH、Conda 等。
- `install.sh` 和模块目录仍调用旧安装器；Proxy 旧链路依赖 Python 运行时及 release_asset/decompress_core/render_config。
- `lib/codex.sh` 调用 prepare-codex.py，proxy/install.sh 调用 find-proxy-backup.py。
- `.github/workflows/check.yml` 仍执行 scripts/check.sh 与旧 Supervisor 集成测试。
- `.github/workflows/release.yml` 仍执行 release-check/bootstrap/release-smoke，打包的是旧 Bash 发行形式；本轮未切换该工作流。
- `make check` / `make dist` 是独立的 Go 验证与发行路径，不依赖上述链路，Go 包只含 stk。

| 清理组 | 文件/范围 | 可清理条件 |
| --- | --- | --- |
| 旧管理入口与菜单 | toolkit.sh、install.sh、codex-launcher.sh、lib/overview.sh、lib/modules.sh | 实际 stk/codex/pm 入口完成切换，外部 Shell/服务引用已检查 |
| 已被 Go 替代的生命周期 | lib/lifecycle.sh、lib/upgrade.sh、lib/transaction.sh、lib/config.sh、lib/doctor.sh、lib/codex.sh、lib/proxy-env.sh | 与旧入口一起退役，不能单独删除被 source 的库 |

| 旧 Python 运行时管理 | lib/python-runtime.sh、requirements/runtime.lock | 所有保留的旧 Python helper 和旧安装入口退役；实际 runtime 目录另行决定，不在源码清理中删除 |
| 旧引导、自更新与发布检查 | scripts/bootstrap.sh、preflight-update.sh、release-check.sh、release-smoke.sh、check.sh、public-audit.sh | Go CI/发布流程切换后整组归档；preflight 仍被旧 lifecycle 引用 |

| 不进入 Go 核心的便捷功能 | lib/conda.sh、git-profile.sh、git-proxy.sh、github-ssh.sh、modules/base-tools、modules/shell、apt-install.sh | 旧入口切换后明确退役或独立保存，不把它们重新扩张进 Go 核心 |
| 可能被外部注册的 helper | scripts/service-start.sh、log-maintenance.sh、ssh-agent.sh、lib/service.sh、lib/common.sh | 检查并解除外部服务/Shell 引用后最后删除 |
| 可选 GDS | gds/src/scheduler.cu、gds/gds.sh、gds/install.sh 及必要说明 | 保留为可选模块资产；未来替换控制脚本后才能精简，不能跟旧管理核心一并删除 |
| VolcML 遗留迁移代码 | prepare-codex.py 的退役 Skill 清理段、tests/platform.sh 中对应测试 | 没有恢复 VolcML 模块；随该旧迁移 helper 整体退役，Go 不读取或改写用户 Skill/AGENTS 内容 |

上述两轮审计没有删除仍在引用链中的旧源码，也没有移动任何实际安装目录。
后续迁移按“先切换工作流、移除失效测试调用，再删除无引用文件”执行。旧管理核心仍需实际入口切换后再清理，GDS 及其依赖保留；组件配置、Skill、认证与运行目录始终不属于源码清理范围。

## 验证方式

- 回归测试覆盖七项原始问题，以及目录嵌套、多次迁移、入口链接、环境主目录、未知配置字段和 YAML 锚点。

- CLI 隔离测试覆盖接管、PATH、挂载改名、更新、卸载、组件与 STK 自身回滚，并逐字节核对认证/会话/数据库哨兵。
- 所有执行使用临时目录、假组件、假控制器和本地 TLS 模拟上游；真实组件仅以只读保护基线核对。
- 第二轮增加 9 项顶层 Go 测试，总计 67 项；覆盖未写入目标的中断恢复、原挂载失踪、连续更新备份边界、预检后的文件/备份变化、执行前迁移检查、禁用代理、共享 YAML、卸载期间编辑和跨实例计划。
- 本地执行 go vet、go test -race 和三组 CLI 隔离测试；交叉编译后的 Linux 测试程序与同一 CLI 脚本在远端私有临时目录运行。CLI 还检查迁移后、repair 前拒绝执行和旧环境输出。
