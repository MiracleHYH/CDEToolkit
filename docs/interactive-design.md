# Nido 统一终端交互设计

本文描述 2026-10-19 当前未发布源码的统一交互实现。公开 v0.9.1 的验收记录保留在 [发行记录](nido-v0.9.1-release.md)，不用于证明本轮实现。具体测试范围和限制见 [构建验证](go-ci-release.md)。

## 主入口

`nido` 在终端打开统一界面，组件分组包含 Proxy、Codex、Conda/pip；Nido 分组直接显示 GitHub Accelerate、Proxy 和检查更新，不另设网络页面。检查后有新版才询问是否更新，无新版提示已是最新版。Shell 自动加载在安装时选择，初始化与环境刷新由安装及配置保存流程内部完成。进入组件后直接显示状态和按视觉分组排列的一级动作，不通过“查看状态”“更新”“生命周期”等子菜单进入操作。分组标题不可选，动作完成后保留页面与选择位置；内容超过窗口高度时滚动。动作中的参数选择属于必要输入，不引入新的操作导航层。

所有组件共用按键、显示、输入、确认和进度规则。菜单和模式选择使用上/下方向键，Enter 执行；确认使用可选择的“取消 / 确认”，默认取消，不要求输入编号或 y/N。Esc 取消当前输入或返回，根页面 Esc 退出；Ctrl+C 取消可取消的任务或安全退出。返回与退出不依赖输入 q。路径、URL 等自由内容仍使用文本字段，密钥隐藏；这些字段中的普通字符不作为菜单退出指令。

公共 UI 层负责终端生命周期、键盘、布局、预览、确认与任务结果；组件仅提供状态、动作及必要输入，不自行读取键盘或拼接 ANSI。业务操作统一委托现有 Manager/Service，不增加另一套 UI 业务后端、动态插件或通用表单 DSL。所有组件共用 Bubble Tea v2、Bubbles 文本字段与 Lipgloss，版本固定于 go.mod，最低构建版本 Go 1.26；用户运行无需 Go。生产只用真实终端，显式注入的 ScriptDriver 仅为 Go 测试接口，不由参数或环境启用。

查看和返回不修改目录、配置或启动服务；查询最新版本、核心校验、上游配置验证均为明确动作。状态记录与实际生效分开描述，配置保存不代表父 Shell 已加载环境。

## 显示、性能与兼容

- 状态在进入页面、操作完成或用户 Ctrl+R 明确刷新时获取；本地 core API 可用于读取运行状态，不隐式查询远端最新版本或发起测速。光标移动不触发业务查询，不增加常驻后台监控或状态轮询。
- 页面变化才更新显示，避免整屏清空、不断追加重复菜单和高频重绘；等待输入时不做无意义工作。进度动画只在任务期间按需启用，不引入装饰动画。
- 网络、下载、查询等耗时操作通过有界异步任务执行，不阻塞键盘与窗口变化处理；提供超时和明确取消语义。同一组件的冲突写操作不能并发执行。取消不承诺撤销已经完成的修改；短暂提交阶段在安全边界处理退出。
- 使用简洁标题、留白、分组分隔和选中高亮。颜色之外仍有文字与选择标记，不依赖 emoji、特殊字体或鼠标。支持无颜色显示及基础字符替代。
- 按终端尺寸布局，正确计算中英文和 ANSI 显示宽度，处理长路径、长代理链的折行与视口滚动；窗口缩放后仍保持选中动作可见。支持普通 SSH、tmux 和常见终端，不要求额外终端扩展。
- 正常退出、可处理的中断和错误返回时恢复终端模式与光标。独立交互命令在恢复后重放最多 16 KiB 的脱敏结果，保留安装完成提示、错误及实际 env.sh 激活命令；菜单动作的结果留在页内。当前官方安装脚本为非交互调用，不添加任意外部交互进程托管层。
- 无 TTY 时不启动 TUI、不等待方向键、不静默切回编号问答；明确子命令和 `--json` 继续用于自动化。缺少必要终端控制能力时清楚报告限制，不能承诺所有终端都支持交互界面。

轻量程度通过启动耗时、空闲 CPU、内存、二进制与依赖增量、SSH 重绘量实测，不以“使用 Go”代替性能证据。交互验证覆盖真实 PTY 方向键/Enter/Esc、确认默认值、取消、终端恢复、中文长文本、窗口缩放、无颜色与非 TTY；此前编号问答测试不能充当新 TUI 的验收证据。

## 配置规则

已有值默认保持；取消尚未提交的选择不写入。提交前显示当前选择、目标值、目标文件和生效方式，最终确认默认不执行。已完成的独立操作不因之后退出菜单而自动回滚。

Proxy 显示安装、配置与运行状态；Codex 显示外部关联状态；Conda/pip 只展示和配置其声明支持的项目，不强迫外部工具具有内置组件生命周期。Quick Start 等流程可以收集必要字段和最终确认，但不再套用多级配置菜单。

某个外部路径不可用应局部报告，不阻止无关组件菜单。主配置结构损坏仍明确报错，不自动重置；写入保留归属、并发、权限与路径检查。

## 网络

GitHub Accelerate 的 None / HTTPS 加速前缀 / Proxy 是三条互斥文件路线：前两条直连原站或加速站，忽略通用 Proxy；第三条保持官方 URL 并引用 Proxy。前缀预填 https://gh-proxy.org，可修改；Proxy 为 None 或可修改的通用代理 URL，启用时预填 http://127.0.0.1:7890。GitHub API 与其他 Nido 对外 API 只使用通用 Proxy，不加前缀。外部安装更新命令通过临时代理环境变量使用同一设置；None 不继承旧代理。无自动回退，不自动启动 Proxy，本地控制接口直连。

不提供 Auto、不跨路线回退。旧自动策略或无效绑定要求重新配置；失败只报告所选路线的错误，不偷偷改为直连或另一代理。

## Proxy

页面上方直接展示 core 状态与 proxy-group 状态。选择关系按 `组名 -> 下游组 -> 最终节点: 最近延迟（测量时间）` 展开；不能确定唯一节点的组、缺失引用或循环引用明确显示对应状态。延迟只展示 core 已有测量，不伪造零值、不把节点延迟累加为整条链路延迟，也不因显示状态自动测速。此前 listener 连通性方案不再作为本页功能要求。

Quick Start、更新内核、更新订阅、重载、重启、停止、启动均直接作为一级动作显示，通过“配置 / 更新 / 运行”等视觉分组分隔，不增加对应子菜单。原生更新由运行中的 core 处理，不为更新自动启动服务；状态展示不扩展为节点编辑、策略组编辑、连接管理或流量仪表盘。

未安装时页面提供“安装 Proxy”，自动下载校验 Mihomo 内核，无独立内核安装入口。安装后选择 Quick Start 或 Skip（默认），已有配置保留复用。Skip 只显示配置路径和后续校验/启动方式，不提供 YAML 导入或日志菜单；高级用户直接操作文件。Quick Start 任何时候可重新进入，保留 Provider、筛选、URI、listeners、独立下载、ISP 与前置链能力。

有配置时确认整体替换，原文字节保存为唯一 `config.yaml.back`。无原配置、同内容、取消、验证失败不更新备份；备份成功才发布新主配置。两文件不承诺跨掉电事务。输入期间并发编辑会阻止覆盖。

可在运行中收集和预览，最终写入前明确停止；配置、启动、重启分别确认。Proxy 不管理工具代理；Codex 运行代理由 Codex 页负责，Nido 通用代理由首页负责。删除 Proxy 先确认停止内核，再删除程序并保留配置与数据。

## 外部集成

Codex 发现按 CODEX_HOME、默认 ~/.codex、自定义路径；可跳过，不移动数据。仅关联、PATH、受管代理和官方安装更新，解除关联不删除数据。

Codex 状态与动作共享一次本地快照。数据目录已关联不代表命令已安装：缺入口时提供官方安装到当前目录，已有且确认 standalone 的入口才提供更新；第三方与未知来源不提供脚本覆盖。重新发现命令是需要确认的关联刷新，不自动写入。动作完成后刷新当前页，不重复查询本地版本或隐式访问远端。

Conda/pip 快捷修改镜像与原生目录配置，不安装工具、不创建环境、不搬动或清理目录。保留首次镜像快照与私有频道保护，交互明确区分官方源、恢复首次设置、停止管理。

## 安装与 Shell

发行工具从已校验的 Linux amd64 包生成自包含 install.sh：压缩程序经 base64 嵌入。仓库只保存极薄 POSIX 模板，包装层只做平台识别、私有临时解包、大小/摘要/版本校验和调用；不联网、不提供传输选择或键盘处理。外层一次下载后就能进入同一 Go TUI，代价是脚本约比压缩包多三分之一传输量。脚本下载与后续策略选择是两个阶段，不推断管道外层 URL。

安装交互从控制终端读取，避免吞掉管道脚本；目录、后续网络设置、确认与 Shell 选择均使用公共 TUI。无终端使用明确参数与 --yes，不等待交互。Shell 注册自愿启用，不执行原配置。当前终端使用安装输出中指向实际软件目录的 env.sh；不声称修改了父进程环境。取消尚未提交的安装不写目录、Shell 配置或组件数据。

GDS 不出现在菜单、帮助、默认构建或发行中；源码独立保留。云平台、镜像、驱动和 Python 环境内部不属于 Nido 管理范围。
