# Nido 配置交互

本轮交互安装、组件配置菜单和可选 Shell 注册属于**源码开发新增，尚未发布**；当前公开版本为 v0.8.2。README 的发行 URL 仍下载公开版本，不会因为本文更新而获得新行为。这里规定交互边界，最终实现和隔离测试通过不等于已发行或已在开发机部署。

## 从明确动作开始

`nido` 及组件裸命令保持帮助或状态行为，不进入全局配置菜单。需要配置时运行相应的短命令：

| 入口 | 负责的选择 |
| --- | --- |
| 安装器 | 软件目录、文件下载方式、可选 Shell 注册；随后委托 `nido init` 初始化 |
| `nido shell setup [bash\|zsh]` | 为选定 Shell 注册实际 Nido 根的加载块 |
| `nido download configure` | 选择 GitHub 文件下载方式，保持 API 绑定和业务代理独立 |
| `nido codex configure` | 外部 HOME 关联、代理及官方安装入口 |
| `nido conda configure` | 分别配置镜像、缓存及环境目录 |
| `nido proxy configure` | 首次生成配置，或明确导入完整私有 YAML |
| `nido gds configure` | 首次输入完整 GPU UUID，或导入配置 |

已有参数继续适用于自动化；缺少值时，终端交互补齐该项，不另造一套组件管理流程。配置菜单使用组件现有校验和写入边界，不复制业务实现或增加后台任务。

## 默认保留已有状态

进入菜单不写入。已有配置默认“保持现状”，新配置显示明确默认值，用户自行确认。镜像选择不连带改变缓存或环境目录，重新进入菜单不覆盖首次 default，不重新捕获认证、会话或数据。

路径使用现有值或产品默认值，不猜测服务器的挂载布局；不提供目录搬运、整盘扫描或异常挂载自动修复。Codex 仍是外部集成，不迁入 Nido；Proxy、GDS 的原生配置保留独立性。

新增向导修改前显示简短摘要，包括目标文件、所选操作和生效方式；Proxy quick start 不展开订阅 URL、节点链接或完整 YAML，持久 default 仍不在普通状态中展开。本轮不引入隐藏输入依赖，交互会提示输入可见；既有显式代理命令可能显示地址，不应将整个 CLI 当成日志脱敏器。原生配置仍由对应组件验证，交互不是放宽文件权限、归属、并发或停止状态检查的理由。

用户可保持或退出，最终确认默认不执行。输入结束或取消不继续提交；已经明确完成的独立操作保留自身结果，不声称后续退出可以回滚之前的修改。

## 安装器保持小而独立

有交互终端时，安装器只询问软件目录、下载方式、可选 Shell 注册和最终确认。下载问题直接回车仅让本次下载使用 `auto`，保留已保存策略；输入新值才保存。注册默认关闭；不把 Codex、Proxy、Conda、GDS 配置塞入下载脚本。

管道安装通过终端读取回答，不从脚本标准输入读取，避免吞掉尚未执行的脚本。没有终端或指定 `--yes` 时保留参数模式；`--dry-run` 不交互、不下载、不安装。

外层脚本下载与内层包下载分开处理。脚本无法从管道推断 curl 的原始 URL；通过私人或预设加速前缀取脚本时，仍应显式传入同一 `--github-proxy`。默认 `auto` 允许官方失败后的有限第三方回退；只有 `direct` 才表示不使用文件加速前缀。HTTPS 和摘要不替代对脚本来源的信任。

安装完成后输出指向实际软件根的环境加载命令，不假设用户最终选择了 `~/.nido`。安装子进程不能修改父 Shell 的 PATH。

## Shell 注册明确选择

`nido shell setup` 是可选的独立动作。用户明确同意后才写入选定 Shell 的受管加载块，保存实际软件根，不执行用户配置文件或启动新 Shell。重复注册保留可证明归属的内容，未知或被编辑的内容不能直接覆盖。

注册为后续读取该启动文件的新 Shell 生效；Bash 的登录配置若未加载 `.bashrc`，仍需自行接入。当前终端仍需手动加载安装输出中的 `env.sh`。不通过在安装期间自动 source `.bashrc` 或 `.zshrc` 来声称已生效，这些文件可能包含平台 hook 或其他有副作用的命令。

## 自动化与预览

| 模式 | 约定 |
| --- | --- |
| 终端 + 缺少值 | 提供候选或输入，默认保留已有配置 |
| 参数齐全 | 沿用该命令的预检和必要确认，不重复询问已给出的值 |
| `--yes` | 跳过确认，不猜测必需的目录、代理、来源或 UUID |
| 无终端 / `--json` | 不进入组件菜单；缺少必需选择时报错，安装器参数模式可使用其明确默认值 |
| `--dry-run` | 不提问，不写配置、不下载安装、不启动服务；未选择的项保持未确定 |

组件的预检范围仍需准确表述。例如 Conda 的显式参数预览可能调用本地工具查询有效配置；它不保存 Nido 选择，但也不是对上游进程的防写沙箱。菜单预览不能把“还没检查”写成“验证通过”。

## 自举与服务边界

API listener 绑定门控保持 v0.8.2 的规则：未绑定时，GitHub API 功能禁用。首次 Proxy/GDS 安装可在终端输入可信本地 artifact 和摘要；这只减少记忆参数的负担，不绕过 API、摘要、架构或候选程序验证。本地候选会执行版本检查，应在导入前完成来源核验。

Proxy 配置完成后仍停止；用户另行运行 `start`，再明确选择 API listener。订阅获取若依赖尚未就绪的代理，仍须准备能完成首次连接的节点或本地配置。交互菜单不自动下载订阅、启用 API、配置其他工具或启动服务来掩盖依赖问题。

GDS 配置不自动选择 GPU 或启动保留显存的工作进程；Codex 配置不控制 daemon。安装、更新、配置和代理绑定均不隐式执行 `start`、`stop` 或 `restart`。
